# Public repository boundary

## Rule

Butter is public and may be consumed by confidential applications.
No Butter planning document, issue, commit, test, pull request, workflow output or release artifact may disclose confidential downstream information.

Security design is public and reviewable.
Consumer secrets, topology, incidents, unreleased weaknesses and product plans remain private.

## Safe public material

- Generic security abstractions and guarantees.
- Synthetic examples and identities.
- Public protocol requirements.
- Generic threat models.
- Sanitized tests and benchmarks.
- Framework limitations that do not describe an unremediated consumer weakness.
- Completed fixes and appropriately timed disclosures.

## Prohibited consumer material

- Consumer names when they are not already intentionally public.
- Private repository URLs, issue links or commit references.
- Database schemas, migrations or row-level security policies.
- Production endpoints, hosts, topology or provider configuration.
- Token, cookie, API key or internal identifier formats.
- KMS configuration or key hierarchy.
- Logs, traces, screenshots, dumps or incident timelines.
- Customer, developer or employee information.
- Credentials, secret names or authentication caches.
- Exploit instructions targeting a confidential consumer.
- Unreleased consumer product plans.

## Local-first defect handling

Internally discovered defects are reproduced and fixed in isolated local worktrees without requiring a GitHub issue.
Consumer-specific evidence stays in the confidential consumer repository or approved local temporary storage.
The Butter worktree receives a generic reproduction and regression test.

Before publication, review the complete Butter diff, commit message, branch name and pull-request text for consumer details.
The public pull request contains only the sanitized framework fix and generic verification evidence.

GitHub issues and security advisories are optional coordination tools rather than mandatory internal workflow.
External reports may still use a separately documented responsible-reporting channel when one is established.

## Public verification isolation

Butter's local verification uses only public source, synthetic fixtures and owned disposable resources.
It never clones a private consumer, reads a consumer token, downloads a private artifact, connects to a consumer database or uploads consumer diagnostics.
No remote CI workflow is configured.
GitHub remains the public source-review and protected-merge boundary, not a cloud builder.

## Cross-repository delivery

A confidential consumer may temporarily exercise a local Butter fix in isolated worktrees.
No local path dependency or moving branch is committed as the consumer's accepted dependency.

After the sanitized Butter change is merged, the consumer pins the reviewed immutable Butter commit.
Consumer-specific policy and tests remain in the private repository.

## Review checklist

- Search the public diff for consumer names and repository paths.
- Search for private hostnames, schema names, endpoints and identifier prefixes.
- Confirm all identities and values are synthetic.
- Confirm logs and screenshots are absent unless generated by the synthetic fixture.
- Confirm commit and pull-request text contains no confidential references.
- Confirm local verification requires no consumer access.
- Confirm the consumer will pin an immutable merged revision.
